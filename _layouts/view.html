{%- when "lab" %}

How to read a tile

The grid resizes to fill your window, so on a small window each tile shows less. Top left is the element number, top right the license (OS open source, Fr free, Fm free tier, Pd paid). The big letters are the symbol, the bar at the bottom is the ring. The formula in each tooltip is its two Compass scores: E easy to use and B made for big, real systems, out of 10.

{%- when "journeys" %}

How to read a journey

Each station is a level. Learn the tools on the line first; branches are worth knowing. Flisk appears on a level only where it does the job today (does it) or part of it (partly). Where it does not yet, it is left off. The gaps are tracked in the Flisk repo.

{%- when "roles" %}

How to read a role card

Each card is one job. The colored strip shows which kinds of tools the job leans on. Must have is what you can't do the job without, Every day is what you touch daily, Good to know is worth learning next. A ★ marks the role's key tools, the ones that set it apart from roles with a similar toolkit. Hover a tool to light it up on every card that uses it; click it to compare.

{%- when "skills" %}

How a skill is tested

A skill is a file that teaches an AI coding agent how to do one job. We test each one with a small, cheap model (Haiku), because if a small model gets it right, a big one will too.

  1. Picked right. Haiku sees the list of skills, like a real agent does, and gets 3 requests: 2 where this skill should be used and 1 that only sounds similar. It scores a point for each request it sends the right way.
  2. Followed right. Haiku reads the whole skill and a real request, then says its first step. A second Haiku call checks that step against the one the skill asks for.

Score: 1 point per request picked right (3) plus 2 points for following right, out of 5, shown out of 100. Further right is better. Green is 80 and up, amber 50 to 79, red below 50. Pick a kind of skill to see them as a leaderboard, best first. Haiku only sees skills from the same repo when it picks, as if you had installed that one collection. The test questions were written from each skill's own text by a stronger model, so a skill is never graded on something it does not claim to do.{% if site.data.skill_evals.model %} Last run: {{ site.data.skill_evals.model }}, {{ site.data.skill_evals.ran | slice: 0, 10 }}.{% endif %}

{%- when "portfolio" %}

How your portfolio works

Rate only what you have really used: 1 used it, 2 use it often, 3 expert. Your best-fit role comes from the {{ site.data.roles.roles | size }} job loadouts on the Roles tab: a must-have tool counts 3, an every-day tool 2, a good-to-know tool 1, each times your level. Many roles share generic tools like GitHub Actions or Terraform, so if you rated none of a role's key tools (marked ★ on its card), its match is halved. Your skill shape adds up your ratings per family of tools.

Your ratings live in your browser and in your page link, so the link is your page. Nothing is sent anywhere until you click Publish my CV: then your ratings and name go to pages.flisk.si, which builds a public CV page you can update or delete with the link you get. Publishing needs a GitHub sign-in (we read only your public login): one CV per GitHub account, at pages.flisk.si/@your-login/cv/. Or download it as a single web page to host it yourself.

{%- when "ask" %}

How Ask works

Ask never calls an AI. It finds the tools you name in this site's data and shows them side by side, the same checklist as the Compass. Name one tool to see its closest alternatives. Name a kind of tool, like "package manager" or "agent framework", to see the best of that kind. Then, if you want an opinion, hand the question and the data to your own AI.
