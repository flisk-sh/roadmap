How it works

{{ tool_total }} developer tools across {{ site.data.families | size }} families, drawn eight ways. Stars, releases and archive notices come live from GitHub every week; see Findings for what the data says. It is a wiki in a Git repo: anyone can open a pull request, and the history of every dot is public.

The four views

  • Compass. Left to right: how easy it is to use. Bottom to top: is it made for small, simple setups, or for big, real systems with many services, databases, Kubernetes, the cloud and big teams? A tool earns 10 points per criterion it meets on each axis.
  • Adoption Radar. Rings from release and maturity signals: Adopt, Trial, Assess, Hold. Each tool links its evidence.
  • Lab. A periodic table of the same tools. The formula on each tile is its two Compass scores.
  • Journeys. Seven levels from your first lockfile to platform architect, walked by three tracks.
  • Roles. {{ site.data.roles.roles | size }} jobs and the tools each one needs: must have, every day, good to know.
  • Skills. {{ site.data.skill_list | size }} free AI agent skills from GitHub, each tested by a small model (Haiku): is it picked for the right request, and is it followed right?
  • Portfolio. Rate the tools you know from 0 to 3. Get your best-fit role, your skill shape and a page you can share. Nothing is sent anywhere until you publish.
  • Ask. Type what you want to compare. The answer comes from this data, with no AI call; you can hand it to your own AI after.

Want the commands, not the scores? cmd.flisk.sh compares what you type for the same job, tool by tool. Tools that are on both sites link across.

Every view has sub-tabs, and each sub-tab has its own address, so you can share exactly what you are looking at. Hover or focus a tool for details. Click up to 5 tools in any view to compare them side by side. Your picks are kept in the address, so you can share a comparison. Logos come from Simple Icons (CC0) and project GitHub organizations; they belong to their owners.

Honesty rules

  • Nobody places a dot by hand. Positions come from the checklist below. To move a dot, change the checklist entries for that tool and say why.
  • {{ meta.publisher }} is on the map like everyone else. {{ meta.publisher }} publishes the site, so it gets no special color, size or position. It sits in Assess because its first release was in October 2026, which is what the rule says.
  • {{ meta.publisher }} appears only where it works. Journeys shows {{ meta.publisher }} on a level only where it does the job today or part of it. The gaps are tracked in the {{ meta.publisher }} repo.
  • The first dataset was written in {{ meta.seeded }}. Expect mistakes. Fixes are welcome.

Fix or add a tool

Tools live in _data/tools/<family>.yml. Edit the file on GitHub, or run ruby scripts/check-data.rb locally before opening a pull request. The contributing guide has the format.

Who decides? For now the maintainers of flisk-sh/roadmap review pull requests against the rules above. If you want to help edit, say so in an issue.
